# Захар и Тедди · Математическая экспедиция

Законченный статический проект математической игры для сильного третьеклассника. Vanilla HTML/CSS/JavaScript, без регистрации, сервера, аналитики, внешних шрифтов и зависимостей в браузере. Зависимости npm нужны только для тестов.

## Играть

На карте 30 уровней: шесть миров по пять. Обычный уровень — 8 задач, испытание — 10. У каждой попытки три сердца. Ошибка забирает сердце и оставляет ребёнка на той же задаче с содержательной подсказкой. Повтор выполняется кнопкой «Попробовать ещё раз». После третьей ошибки уровень заканчивается без звёзд. Завершение уровня даёт столько звёзд, сколько осталось сердец, и открывает следующий. Лучший результат не ухудшается.

Таблица умножения и деления от 2 до 9 открывается в меню. Свободная тренировка не отнимает сердца и не меняет сюжетный прогресс. Во время просмотра справочника или настроек переход к следующей задаче приостанавливается.

Ответы вводятся с физической или экранной клавиатуры. Цифры и NumPad вводит нативный input; Backspace редактирует, Delete/Escape очищают, Enter проверяет. Tab остаётся браузерной навигацией. Для остатка Enter после частного переводит фокус во второе поле. Кнопки пишут в последнее сфокусированное поле и всегда дописывают цифру справа. При ошибке, успехе и победе меняются позы персонажей.

## Запуск и проверка

Нужен Node.js 22 или новее.

```bash
npm ci
npm test
npm run build
npm start
```

Открыть адрес, который напечатает сервер. Файл index.html использует ES-модули, поэтому для локальной игры нужен HTTP-сервер, а не открытие через file://.

Настоящие браузерные тесты:

```bash
npx playwright install --with-deps chromium webkit
npm run test:e2e
```

## GitHub Pages

В корне репозитория должны находиться package.json, package-lock.json, public/, scripts/, tests/, playwright.config.js и .github/. Имя репозитория может быть любым: все ресурсы подключены относительными ссылками и работают под путём /repository-name/.

Источник публикации в Settings → Pages → Build and deployment: **GitHub Actions**. Workflow `.github/workflows/pages.yml` при push в main или ручном запуске устанавливает зависимости, выполняет тесты ядра и DOM, затем Chromium и WebKit, собирает dist и публикует Pages. При падении проверки публикация не выполняется. Для pull request выполняются только проверки.

Публикуется только dist: исходники тестов, dev-сервер и конфигурация не попадают в сайт. Никаких секретов или переменных окружения для самой игры не требуется. Конфигурация соответствует [официальному руководству GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Причина старого бага 15 → 51

В предыдущем проекте обнаружена работа экранных кнопок с selectionStart поля, утратившего фокус. На сенсорных устройствах позиция могла оставаться равной нулю. Новая цифра вставлялась перед предыдущей. Это подтверждается старым модулем answer-input.js и описанием предыдущего исправления; это не проблема арифметики и не повод использовать reverse().

В новой игре физические цифры обрабатывает браузер через input/beforeinput. Общего обработчика, который повторно вставляет физическую цифру, нет. Экранные кнопки используют чистую функцию editAnswer(previous, {type:'append', digit}), то есть previous + digit. Общий объект fields хранит оба поля и выбранный вариант. Поле явно LTR. Позиция курсора не участвует во вводе экранными кнопками.

## Корректность математики

Генератор не разбирает HTML и не использует eval. Точное деление строится как divisor × quotient. Остаток создаётся в интервале 1…divisor−1. Смешанный уровень 23 содержит отдельные задачи точного деления с одним полем и задачи с остатком с двумя полями. Нулевой остаток возможен в вопросах о свойствах остатка, но не выдаётся как задача «с остатком».

AST проверяет каждый операнд и промежуточный результат: целое число 0…1000, без деления на ноль и дробных частных. Обычные делители однозначные; :10 и :100 присутствуют только в специально запрошенных заданиях уровня 14. Уравнения создаются из выбранного неизвестного, а правая часть вычисляется по AST. Уровни 19 и 26–30 отмечены «Сириус+». Название означает наше игровое усложнение, а не официальную программу или связь с организацией «Сириус».

Каждый запуск получает новый seed. Он сохраняется вместе с подписью последовательности задач. Один seed воспроизводит тот же набор; совпадение последовательности с предыдущей попыткой вызывает повторную генерацию. Внутри попытки Set исключает одинаковые формулировки. Испытания используют перемешанное расписание навыков: все заявленные навыки попадают в попытку.

## Сохранение и сброс

Ключ localStorage: `zakhar-teddy-game:v2`, `schemaVersion: 2`. Хранятся completedLevels, bestStarsByLevel, skillStats, lastAttemptSeedByLevel, lastAttemptSignatureByLevel, records, currentLevel, unlockedLevel и settings. Незавершённая попытка после обновления начинается заново; ранее заработанные звёзды остаются. Сохраняется текущий выбранный уровень. Сохранения локальны для браузера и устройства.

Повреждённые данные и неизвестная версия дают безопасное начальное состояние. Доступные уровни восстанавливаются по непрерывной последовательности результатов. Если хранилище заблокировано, игра продолжает работать и сообщает, что прогресс может не сохраниться.

Сброс имеет отдельное подтверждение, удаляет только ключ игры и записывает чистое состояние. Удаляются также статистика, рекорды, seeds и подписи попыток. Данные других сайтов/игр и sessionStorage не затрагиваются. Авторизации в проекте нет.
